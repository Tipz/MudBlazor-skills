# MudBlazor Skills

Набор offline-first skills для Codex, предназначенный для разработки бизнес-интерфейсов на стеке:

- .NET 10
- Blazor Web App
- Interactive Server
- MudBlazor
- Clean Architecture и Vertical Slice Architecture

Skills используют локальные файлы проекта и включённые в репозиторий справочные материалы. Для обычной работы им не требуются React, Vue, Tailwind, shadcn/ui, Node.js или доступ в интернет.

## Состав репозитория

| Skill | Назначение |
| --- | --- |
| `blazor-webapp-offline` | Жизненный цикл Blazor, render modes, состояние, навигация, circuits, инфраструктура форм и JS interop |
| `mudblazor-offline` | Выбор компонентов, проверка конкретных API установленной версии и диагностика ошибок MudBlazor |
| `ui-ux-pro-max` | Пользовательские сценарии, interaction model, валидация, состояния, доступность и UX насыщенных данными desktop-приложений |
| `frontend-design` | Визуальная иерархия, композиция, интервалы, типографика, плотность, адаптивность и визуальное ревью |

При комплексной работе над интерфейсом skills используются в следующем порядке:

```text
ui-ux-pro-max
    -> frontend-design
    -> mudblazor-offline
    -> blazor-webapp-offline, если затронуто поведение платформы
```

Каждый `SKILL.md` сделан компактным и подключает тематические файлы из `references/` только при необходимости.

Набор routing-кейсов для проверки автоматического выбора skills находится в `evals/routing.csv`.

## Использование с Codex

Клонируйте репозиторий в проект или скопируйте нужные каталоги skills в `.agents/skills/`:

```text
.agents/
`-- skills/
    |-- blazor-webapp-offline/
    |-- frontend-design/
    |-- mudblazor-offline/
    `-- ui-ux-pro-max/
```

После этого Codex сможет выбирать подходящий skill по описанию в frontmatter. Точные API платформы и MudBlazor проверяются по локально установленному SDK, пакетам, сгенерированным файлам и существующему коду проекта.

## Offline-first подход

- Для обычной работы не требуется поиск в интернете.
- Восстановление и обновление пакетов или скачивание шаблонов не выполняются автоматически.
- Если локальный SDK или пакет отсутствует, skill сообщает об этом, а не пытается угадать API или загрузить зависимость.
- Включённые references содержат рекомендации, но источником истины остаются целевой проект и установленные версии пакетов.
